## Change
Build a separate trusted Tailscale gateway on default-policy Cloudflare Containers, bounded HTTP GET/TCP probe/fixed SSH verification tools, allowlisted peers/ports, secret provisioning and finite verification. Agent-generated shell code is never run in the gateway and never receives its enrollment key. The native arbitrary-code sandbox remains source-blocked. Owner explicitly requested building access, minting a fresh key and storing it in Wrangler/Cloudflare secrets.

## Billable paths
One opt-in gateway container/application/SQLite object, Tailscale enrollment/relay traffic and private-server requests, existing singleton tool/execution/runtime/network/storage reservations and admin request admission. Key provisioning makes finite administrative Tailscale/Cloudflare API calls. No inference, autoscaling, polling, idle keepalive or periodic key minting. No resource or hosted test is created until usable management authentication and an approved target/tag exist.

## Worst-case bounds
Default scheduling max_instances=1, lite resources, fixed trusted 75-second gateway program lifetime and 90-second durable lease. Reuse the SAME global sandbox slot and existing counters (3 attempts/day, 10/month, legacy limits may deny earlier). One HTTP GET, TCP probe or fixed read-only SSH marker/id command per admitted execution, 20-second request deadline, 10-second SSH process deadline, 8KiB HTTP body or 512-byte banner/SSH output; 8MiB network reservation and 6MiB storage reservation retained. Tailnet daemon control/relay overhead is not a measured 8MiB invoice cap. Egress enabled only for trusted fixed code, never arbitrary agent shell. No general SOCKS proxy is exposed to agent code. Existing quotas unchanged.

## Failure and retry
No automatic creation/retry/replay/key rotation; provider failures consume reservations. Key mint is at most one create plus one secret upload and metadata-only receipt; if upload fails, revoke minted key once. Enrollment/auth/API timeouts bounded. Durable operation journal returns existing completion or rejects interrupted replay. Destroy before global slot release; unknown cleanup latches global stop and retains the slot. Single cleanup alarm, no self-rescheduling loops. Native hosted verification stops at first denial.

## Emergency stop
Existing owner global stop independently destroys gateway and blocked coding sandbox; status stays owner-readable while stopped. Fixed trusted gateway exits after 75 seconds even if the DO request is lost, with no agent code capable of changing it. Application/network output is capped; out-of-band endpoint disable remains needed for ingress/unreachable Worker. Key revocation and Tailscale device removal are separate controls, not implicit deletion of an existing server.

Ten actual Python tests passed using local SOCKS/HTTP sockets, bounded SSH subprocess output and fake provisioning APIs. Typecheck, billing gate and guarded Worker dry-run passed. Docker image build uses the owner-approved SSH host; only public source is sent. CI uses public runner without Tailscale/Cloudflare secrets or hosted connections. One management key created and uploaded as CF secret; a dedicated owner-managed source/destination tag and SSH-only rule added, preserving existing server tags and grants. Host Tailscale SSH proved root access; coder/ubuntu denied. ## Residual risks
Management credential now works and remains local. Owner selected ubuntu-1 SSH; dedicated target tag limits the new SSH rule to that host/root. Existing wildcard network grants remain unchanged, so the enrollment identity is not ACL-isolated to one server; the trusted fixed service enforces the application allowlist. Tightening existing grants requires a separate tailnet policy review. Broad reusable enrollment credentials are prohibited; new key limited to a dedicated non-admin tag, ephemeral nodes, one-day expiry. Gateway needs Tailscale relay/control internet and consumes tailnet plan/device allowances; storage/DO/ingress/relay/cleanup may still bill. Arbitrary code isolation block is not removed. TCP probe establishes connectivity only; the fixed SSH check proves authentication but does not expose a general remote-command shell. TLS verification stays on; redirects and user-supplied headers/auth are rejected. No credential values in transcripts/logs/git.
